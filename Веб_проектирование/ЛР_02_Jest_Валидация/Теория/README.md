# Что происходит в тесте

```javascript
test('принимает возраст 14', () => {
  expect(isValidAge(14)).toBe(true);
});
```

`test` регистрирует проверку. Первый аргумент — понятное название. Второй — функция, которая выполнится при запуске тестов. `() => { ... }` — стрелочная функция без аргументов. `expect` получает результат, `toBe(true)` сравнивает его с ожидаемым значением.

`describe` объединяет связанные проверки. `toBeTruthy` допускает любое значение, считающееся истиной; `toBe(true)` проверяет именно true. Поэтому обязательные truthy/falsy-примеры дополняйте строгими проверками, чтобы случайное возвращение строки не прошло незамеченным. `toEqual` сравнивает структуру объектов, а не одну и ту же ссылку.

`typeof age === 'number'` не проверяет целочисленность. `Number.isInteger(age)` отвергает строку '18', дробь, NaN, Infinity и true. `&&` означает «и» с коротким замыканием: после ложного первого условия второе не вычисляется. Это позволяет проверить строковый тип до чтения .length.

Регулярное выражение `/шаблон/` описывает допустимый текст. В email-примере `^` — начало строки, `$` — конец, `+` — один и более символов, `[^\s@]` — не пробел и не @, `\.` — буквальная точка. Это учебная проверка структуры, а не полная реализация RFC и не проверка существования почтового ящика.

Для пароля `/\p{L}/u` проверяет наличие буквы любого алфавита, `/[0-9]/` — цифры. `u` включает Unicode-режим. Вариант явно трактует длину через стандартное JS string.length; это не число видимых графем.

CommonJS: `module.exports = {...}` экспортирует, `require('./validators')` импортирует. Не смешивайте его с type:module из предыдущей ЛР: здесь отдельный package.json с type:commonjs.

Основа: [Jest запуск](https://jestjs.io/docs/getting-started), [matchers](https://jestjs.io/docs/using-matchers), [MDN регулярные выражения](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Regular_expressions).
