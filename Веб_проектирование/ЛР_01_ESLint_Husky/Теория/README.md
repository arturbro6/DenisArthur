# Теория простыми словами

**Линтер** анализирует исходный текст. Он находит, например, необъявленную переменную. Он не доказывает, что калькулятор правильно складывает: логическую ошибку проверяют тестами.

**Git-хук pre-commit** — команда перед созданием коммита. Ненулевой код завершения отменяет коммит. **Husky** помогает хранить и подключать такие команды. Связь: git commit → pre-commit → npm run lint → ESLint → успех или ошибка.

| Конструкция | Как читать |
|---|---|
| `npm install -D` | Пакеты нужны для разработки |
| `npx husky init` | Выполнить команду Husky и подготовить хук |
| `"lint": "eslint ."` | Имя команды и её содержимое в package.json |
| `.` | Текущий каталог |
| `import ... from ...` | Подключить модуль ES Modules |
| `export function add` | Сделать функцию доступной другим модулям |
| `...globals.browser` | Разложить свойства объекта в новый объект |
| `export default [...]` | Основной экспорт массива настроек |
| `"error"` | Нарушение должно завершать проверку ошибкой |

У Husky 9 используется init; старые команды из других руководств могут отличаться. В этом учебном варианте зафиксирована ветка ESLint 9 и Husky 9; точные установленный версии нужно записать в собственный package-lock.json. Конфигурация flat config отличается от старого .eslintrc.

`.gitignore` исключает node_modules и служебные файлы, но не скрывает уже отслеживаемые файлы. package-lock.json фиксирует зависимости и сохраняется в Git. Скрипт prepare запускает подключение Husky после установки зависимостей.

Источники: [Husky](https://typicode.github.io/husky/get-started.html), [ESLint конфигурация](https://eslint.org/docs/latest/use/configure/configuration-files), [среды](https://eslint.org/docs/latest/use/configure/language-options), [материал Moodle по линтерам](https://moodle.herzen.spb.ru/mod/url/view.php?id=1372321).
