# Порядок работы

## 1. Сделайте отдельную тренировочную папку

Примеры лежат внутри общего репозитория. Для первой тренировки скопируйте файлы Вариант_решения в папку вне клона и выполните там `git init`. Не создавайте вложенный Git-репозиторий внутри DenisArthur: это осложнит добавление файлов. Для настройки хука прямо в общем репозитории он должен находиться в его корне и запускать линтер нужной подпапки; такой перенос делайте после понимания обычного проекта.

Проверьте `node --version`, `npm --version`, `git --version`. Используйте поддерживаемую Node.js LTS; пример рассчитан на Node 22 или новее. В папке выполните `npm init -y`, если package.json ещё нет. Если скопировали приложенный package.json, повторная инициализация не нужна.

## 2. Установите инструменты

`npm install -D --save-exact eslint@9 @eslint/js@9 globals husky@9`

Это выберет точные версии внутри указанных веток и сохранит lock-файл. Не устанавливайте latest вслепую поверх несовместимой методички. Запишите `npm ls --depth=0` в собственный отчёт.

## 3. Проверьте конфигурацию

Прочитайте eslint.config.js. Первый элемент — рекомендуемые правила JavaScript, второй — среда и правила. В package.json есть `"type":"module"`, поэтому import/export понимаются как ES Modules. В руководстве преподавателя предлагается интерактивная настройка; при использовании мастера выберите указанные в условии опции и сравните итог с примером.

## 4. Сначала запустите линтер вручную

`npm run lint` должен завершиться без ошибок для исправного calc.js. Отдельно `node calc.js` покажет результаты арифметики. Подумайте: `return a-b` внутри add синтаксически корректен — линтер может пропустить его. Поэтому нельзя писать «ESLint проверил правильность вычислений».

## 5. Подключите хук

В корне отдельного учебного Git-проекта выполните `npx husky init`. В `.husky/pre-commit` оставьте строку `npm run lint` вместо стартового `npm test`. Добавьте сам файл хука в Git, а не служебный каталог `.husky/_`. Проверьте `git config --get core.hooksPath`: после инициализации Husky он должен указывать на созданную инфраструктуру.

## 6. Получите настоящую блокировку

Сохраните исправный calc.js отдельно, затем замените его содержимым calc.broken.txt. Там намеренно есть неиспользуемая переменная и обращение к необъявленному имени. Выполните `git add calc.js`, затем попытку коммита. Должны появиться ошибки ESLint; новый коммит не создаётся. Сделайте скриншот именно своего терминала.

Верните исправный calc.js, повторите git add и коммит. Сохраните второй скриншот. После исправления обязательно обновить индекс через git add: иначе в индексе останется старая версия.

## 7. Экспериментальный вариант

В docs/PROMPTS.md находится пустая таблица для реальных записей. Сначала самостоятельно объясните ошибку, затем спросите DeepSeek. Ролевой запрос: попросите объяснить flat config с учётом версий. Zero-shot: запросите .gitignore без примера. One-shot: покажите пример хука с npm test и попросите адаптировать под lint. Для каждого ответа проверьте команды, запишите принятое и отклонённое. Токены и личные данные не отправляйте.

## Самостоятельный шаг

Объясните, почему изменение функции add на вычитание не обязательно блокирует коммит. Добавьте свой тест арифметики. Затем проверьте, почему файл с ошибкой может быть проигнорирован линтером — изучите files/ignores, не отключайте правило ради зелёного вывода.

Неисправности: `Cannot use import` — проверьте type:module; `.git can't be found` — вы не в корне тренировочного Git-проекта; линтер находит console как неизвестный — проверьте Browser/Node globals; хук не сработал — проверьте prepare и core.hooksPath.

К сдаче: код, конфигурация, package-lock, хук, README с объяснением пайплайна, два ваших скриншота; для экспериментальной группы — ещё журнал и скриншоты запросов.
