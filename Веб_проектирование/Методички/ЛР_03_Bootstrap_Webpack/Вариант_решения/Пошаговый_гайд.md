# Пошаговая методичка

## 1. Разделите два этапа

В этой папке есть Шаг_1_Сетка и Шаг_2_Аккордеон. Это два снимка одного учебного проекта, а не два проекта для одновременной установки. Начните с первого; во второй заглядывайте после проверки сетки. Для сдачи потребуется ваш один репозиторий с историей перехода между этапами.

## 2. Проверьте окружение

Нужны Node.js LTS (пример ориентирован на 22+), npm, Git, редактор и DevTools. Создайте отдельную тренировочную папку вне общего клона. Скопируйте туда файлы первого этапа. Выполните `npm install`, сохраните package-lock. На новых компьютерах используйте `npm ci` с этим lock-файлом.

В package.json версии инструментов заданы совместимыми major-ветками. Для своей сдачи зафиксируйте конкретные выбранные версии через --save-exact и приложите lock. Не обновляйте Bootstrap до следующей major-версии.

## 3. Прочитайте webpack.config.cjs

Сначала найдите entry и output. Объясните, почему clean:true безопасен именно при output.path=app/dist и опасен, если по ошибке указать весь app. Затем прочитайте правило SCSS справа налево по теории. Конфиг — исполняемый JavaScript-объект, а не JSON: здесь разрешены require и создание плагина через new.

## 4. Проследите единственный импорт

src/js/main.js на первом этапе импортирует только ../scss/main.scss. В main.scss сначала инфраструктура, затем containers и grid, затем собственный page. Никакого полного bootstrap/scss/bootstrap. _page.scss начинается с box-sizing:border-box, потому что Reboot в минимальной сборке отсутствует.

## 5. Запустите и проверьте сетку

`npm start`, откройте localhost:8080. В DevTools включите адаптивный режим и установите 375,800,1200. Предскажите число колонок до изменения ширины. Dev-server обычно отдаёт сборку из памяти; для проверки файлов на диске остановите сервер и выполните `npm run build`.

Проверьте: app/index.html сохранился; в app/dist появились styles.css и bundle.js. Найдите в CSS .container, .row, .col-md-6; на этом этапе не должно быть .accordion-button, .modal и .btn-primary. В Network не должно быть Bootstrap CDN. Создайте требуемый заданием коммит demo-grid в своём проекте.

## 6. Измерьте макет самостоятельно

Откройте макет Pixso по ссылке из условия. Для закрытого и открытого пункта выпишите фон, цвет текста, шрифт, размер, отступы, границу, радиус, значок и фокус. Заполните docs/design-values.md. Пример _theme.scss содержит только демонстрационные значения — это не измерения Pixso.

## 7. Добавьте аккордеон

Во втором этапе изменены HTML, main.js и main.scss, добавлен _theme.scss. Сравните файлы между этапами. В SCSS добавлены root, transitions и accordion: root обеспечивает CSS-переменные, transitions — поведение скрытия и промежуточного раскрытия, accordion — внешний вид. В JS подключён только bootstrap/js/dist/collapse. Не импортируйте весь JS Bootstrap и CDN-бандл.

## 8. Настройте SCSS, не закрашивайте всё !important

Таблица docs/design-values.md связывает параметр макета и SCSS-переменную. Найдите соответствующие переменные в _variables.scss установленной Bootstrap. Задайте свои значения в _theme.scss до импорта variables. Если подходящей переменной нет, объясните необходимость небольшого собственного CSS.

## 9. Проверьте поведение

Раскрываются все пункты, предыдущий закрывается, первый открыт согласно show/aria-expanded. Проверьте Tab, Enter, пробел и видимый фокус; длинный текст переносится, горизонтальной прокрутки нет. Сопоставьте оба состояния с макетом. После правки SCSS пересоберите CSS: изменение исходника само по себе не меняет уже собранный файл.

## 10. Разберитесь с экспериментальной группой

Сначала составьте собственный план. В SourceCraft подключите Context7 по инструкции исходного PDF; для макета — Pixso Desktop и его MCP. До изменения файлов попросите документацию и план, потом проверяйте diff и команды. Сохраните реальные скриншоты обращений и заполните docs/ai-log.md. Этот гайд не является свидетельством уже выполненных вами обращений к MCP. Если инструмент не работает, зафиксируйте ограничение и согласуйте альтернативу с преподавателем.

## 11. Подготовьте публикацию

В pages.yml.example показан workflow, его нужно понимать до переноса в .github/workflows/pages.yml **корня своего репозитория**. Запуск из вложенной папки сам по себе не активирует GitHub Actions. Workflow устанавливает зависимости, собирает проект и публикует весь app. Папка app становится корнем сайта; добавлять /app/ к URL обычно не требуется.

Для публикации проекта прямо из общего DenisArthur нужно изменить working-directory, cache-dependency-path и path артефакта на соответствующую подпапку. В примере дан отдельный учебный репозиторий, чтобы не переключать общие настройки Pages автоматически.

## 12. Подготовьте свой Отчет.docx

Авторство, исходная задача, выбранные части Bootstrap, команды и реальные версии, схема файлов, таблица SCSS-переменных, скриншоты трёх ширин и состояний, ссылка на GitHub и работающий Pages. Для экспериментальной группы — журнал и скриншоты инструментов. Шаблон плана отчёта лежит в docs/REPORT_PLAN.md.

## Самостоятельный шаг

Временно уберите импорт Collapse и предскажите, что перестанет работать. Верните его. Затем уберите transitions: выясните, почему начальное скрытие и анимация нарушаются. Объясните разницу между отсутствующим CSS и отсутствующим JS.

Частые ошибки: весь Bootstrap вместо выборки; HTML внутри очищаемого dist; неверные относительные URL; попытка проверить файлы на диске только после dev-server; _theme после variables; повторяющиеся id; публикация только app/dist без HTML.
