# Требования

В оригинальной standalone HTML-странице можно изменить только тело task(order) и значение LOGIN. Не менять форму, URL-разбор, #result, глобальную доступность window.task и остальной преподавательский код.

Вход:

```javascript
task({ items: { notebook: 2, marker: 1 }, promo: "STUDENT", pickup: false });
```

items — объект «код товара → количество»; promo — пустая строка или STUDENT для корректного заказа; pickup — логическое значение. Некорректные количества и промокоды проверяются отдельно. Произвольные отсутствующие поля заказа в задании не специфицированы: не добавляем для них выдуманные коды ошибок.

| Код | Цена | Остаток |
|---|---:|---:|
| notebook | 250 | 8 |
| marker | 90 | 12 |
| folder | 120 | 6 |

Нужны целые неотрицательные количества, известные товары, соблюдение остатков и хотя бы одна единица товара. STUDENT даёт 10% суммы товаров с округлением скидки вниз. Другой непустой промокод — ошибка. Самовывоз бесплатный. Иначе доставка 150, кроме суммы после скидки от 1000 включительно. Заказ не изменять; склад не уменьшать между вызовами.

Успех: {ok:true,subtotal,discount,delivery,total}; ошибка: {ok:false,error}. Коды: unknown-item, invalid-quantity, out-of-stock, empty-cart, bad-promo. Согласно PDF одновременно не более одного типа ошибки, приоритет конфликтующих ошибок не задан.

Проверяющий использует URL-параметры и window.task(...). Ответ страницы — JSON в #result. В Moodle отправляется корневой публичный HTTPS-адрес страницы, без параметров тестового заказа. Отправка в форум в рамках подготовки этой методички не выполнялась.
