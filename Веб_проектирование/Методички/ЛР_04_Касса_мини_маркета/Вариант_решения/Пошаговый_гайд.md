# Выполняем лабораторную с нуля

## 1. Подготовить исходную страницу

Скачайте именно mini_market_starter.html из Moodle и сохраните копию. Откройте файл в VS Code через File → Open File. Найдите текст `function task(order)` поиском Cmd+F (Mac) / Ctrl+F (Windows). Найдите LOGIN. Не заменяйте всю страницу нашим task.js: это только функция, а в оригинале есть нужные форма и чтение URL.

Замените значение LOGIN своим логином Moodle, сохранив кавычки и способ объявления из шаблона. Не путайте логин с ФИО. Значение не подставлено автоматически: в полученном условии оно пустое.

## 2. Сначала посчитать вручную

Две тетради и маркер: 2×250+90=590. Скидка 59. Остаток 531, меньше 1000, доставка 150. Итого 681. Запишите эти числа до чтения кода.

## 3. Создать каталог внутри task

```javascript
const catalog = {
  notebook: { price: 250, stock: 8 },
  marker: { price: 90, stock: 12 },
  folder: { price: 120, stock: 6 }
};
let subtotal = 0;
let quantity = 0;
```

Каждый товар — маленький объект внутри общего объекта. subtotal суммирует рубли, quantity — число единиц. Это разные величины. Точки с запятой заканчивают инструкции; фигурные скобки здесь описывают объекты. Отступы улучшают чтение; пары скобок должны совпадать.

Это промежуточный фрагмент, его одного недостаточно для готовой функции. Полный вариант ниже: не вставляйте повторно переменные, если они уже добавлены.

## 4. Проверить каждую позицию до умножения

Порядок одного прохода цикла: пропустить унаследованное поле входа → проверить товар → получить count → проверить целое и неотрицательное → проверить остаток → накопить количество и стоимость.

Почему именно так: если товара нет, обращение catalog[code].stock могло бы вызвать ошибку вместо объекта unknown-item. Если count строка, арифметика может неявно преобразовать её, скрыв недопустимый тип. Если count=0 для известного товара, позиция допустима; но весь заказ из нулей будет пустым. Неизвестный товар с нулём всё равно неизвестный.

Проверка `!Number.isInteger(count) || count < 0` читается «не целое ИЛИ меньше нуля». При ошибке return немедленно завершает вызов. Знак минус в коде ошибки — внутри строки: `"invalid-quantity"`.

## 5. Проверить весь заказ и промокод

После завершения цикла quantity===0 означает empty-cart. Промокод допустим только если равен пустой строке или STUDENT. Условие ошибки использует &&: одновременно не пустой и не STUDENT. Проверка чувствительна к регистру и пробелам: student и ` STUDENT` не равны STUDENT. Не используйте trim или toUpperCase — условие не разрешает исправлять промокод за покупателя.

В PDF обещан максимум один тип ошибки на вход. Не нужно придумывать универсальный порядок приоритета для сочетания неизвестного товара и неверного промокода: такой контракт не задан.

## 6. Посчитать скидку, затем доставку

Размер скидки — Math.floor(subtotal/10), если promo строго STUDENT; иначе 0. afterDiscount=subtotal-discount. delivery начинается со 150; если pickup=true ИЛИ afterDiscount>=1000, меняется на 0. total=afterDiscount+delivery.

Контрольный пример: четыре тетради без скидки стоят ровно 1000, доставка бесплатна. С промокодом скидка 100, остаток 900, доставка снова платная, итог 1050. Самовывоз убирает доставку при любой допустимой непустой корзине.

## 7. Перенести полный код в заготовку

Ниже функция целиком для чтения. По требованию преподавателя замените только текст МЕЖДУ открывающей фигурной скобкой существующей task и её соответствующей закрывающей скобкой. Заголовок и внешнюю скобку не дублируйте. Остальные функции и window.task страницы сохраните.

```javascript
function task(order) {
  const catalog = {
    notebook: { price: 250, stock: 8 },
    marker: { price: 90, stock: 12 },
    folder: { price: 120, stock: 6 }
  };
  const owns = (object, key) => Object.prototype.hasOwnProperty.call(object, key);
  let subtotal = 0;
  let quantity = 0;

  for (const code in order.items) {
    if (!owns(order.items, code)) continue;
    if (!owns(catalog, code)) {
      return { ok: false, error: "unknown-item" };
    }
    const count = order.items[code];
    if (!Number.isInteger(count) || count < 0) {
      return { ok: false, error: "invalid-quantity" };
    }
    if (count > catalog[code].stock) {
      return { ok: false, error: "out-of-stock" };
    }
    quantity += count;
    subtotal += catalog[code].price * count;
  }
  if (quantity === 0) {
    return { ok: false, error: "empty-cart" };
  }
  if (order.promo !== "" && order.promo !== "STUDENT") {
    return { ok: false, error: "bad-promo" };
  }

  let discount = 0;
  if (order.promo === "STUDENT") {
    discount = Math.floor(subtotal / 10);
  }
  const afterDiscount = subtotal - discount;
  let delivery = 150;
  if (order.pickup || afterDiscount >= 1000) {
    delivery = 0;
  }
  const total = afterDiscount + delivery;
  return { ok: true, subtotal, discount, delivery, total };
}

```

Проверьте, что на странице осталось одно объявление task, а заглушка not-implemented внутри неё удалена. Сохраните Cmd+S / Ctrl+S. Откройте HTML в браузере. В форме задайте 2 тетради, 1 маркер, STUDENT, доставку; ожидается объект с subtotal=590, discount=59, delivery=150, total=681.

## 8. Проверить прямые вызовы в Console

В браузере откройте инструменты разработчика → Console. На Mac обычно Cmd+Option+J; можно выбрать консоль через меню браузера. Введите:

```javascript
window.task({items:{notebook:2,marker:1},promo:"STUDENT",pickup:false})
```

Ожидаемый объект:

```json
{"ok":true,"subtotal":590,"discount":59,"delivery":150,"total":681}
```

Затем введите отдельно каждый случай:

| Вызов: items / promo / pickup | Ожидание |
|---|---|
| {notebook:4} / пустой / false | 1000, 0, 0, 1000 |
| {notebook:4} / STUDENT / false | 1000, 100, 150, 1050 |
| {folder:1} / пустой / true | 120, 0, 0, 120 |
| {notebook:9} / пустой / false | out-of-stock |
| {marker:-1} / пустой / false | invalid-quantity |
| {marker:1.5} / пустой / false | invalid-quantity |
| {marker:"2"} / пустой / false | invalid-quantity |
| {coffee:1} / пустой / false | unknown-item |
| {} / пустой / false | empty-cart |
| {notebook:0,marker:0,folder:0} / пустой / false | empty-cart |
| {folder:1} / SAVE / false | bad-promo |

Для успеха в таблице порядок чисел: subtotal, discount, delivery, total. Пустой промокод в коде записывается `promo:""`, а не словом «пустой».

Проверка входа без изменения:

```javascript
const original = {items:{notebook:2},promo:"STUDENT",pickup:false};
const before = JSON.stringify(original);
window.task(original);
console.log(JSON.stringify(original) === before);
```

Ожидается true. Вызовите task с тем же заказом ещё раз: результат должен повториться. Проверяющий может делать много вызовов, поэтому склад нельзя уменьшать глобально.

## 9. Запустить автоматические проверки при наличии Node.js

Откройте в VS Code папку с task.js и test_task.cjs. В терминале выполните:

```bash
node test_task.cjs
```

Node запускает отдельную функцию из task.js, а не интерфейс HTML. Проверки не требуют npm install и сторонних библиотек. Они охватывают пять открытых примеров, недопустимые типы, остатки, пустую корзину, неизвестные ключи, неизменность и все сочетания допустимых количеств. Успех этих тестов ещё не означает, что HTML правильно опубликован.

## 10. Получить публичную HTTPS-страницу

В исходном задании не требуется менять сборку Bootstrap, ставить Webpack или переписывать форму. Это отдельная standalone HTML-работа. Для отдельного учебного сайта сохраните исходную страницу с изменённой task как index.html в каталоге публикации. Если в общем репозитории уже работает Pages другой работы, сначала проверьте его настройки: не заменяйте существующий сайт случайно. Можно выделить каталог cash внутри существующего публикуемого каталога; адрес тогда заканчивается /cash/.

При публикации через GitHub Pages выбирается источник в Settings → Pages; конкретная ветка/каталог или workflow должны соответствовать текущему устройству сайта. Подробности: [документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site). Если Pages недоступен, согласуйте другой HTTPS-хостинг с преподавателем. Ссылка на файл github.com/.../blob/... не является работающей страницей приложения; file:/// с ноутбука тоже не подходит.

## 11. Проверить именно опубликованный адрес

Откройте его в отдельном окне. Добавляйте к URL параметры из открытых примеров, например `?notebook=4&promo=STUDENT`. Страница сама должна заполнить #result правильным JSON без нажатия кнопки. Повторите `window.task(...)` в Console опубликованной страницы. Проверьте LOGIN.

В Moodle по условию отправляется один корневой HTTPS-адрес страницы без параметров конкретного заказа. Форум и публикация здесь ещё не выполнены: их нельзя считать готовыми по одному test_task.cjs.

## Ошибки и самостоятельная проверка понимания

- Нет window.task: вероятно, затронут внешний код заготовки или есть синтаксическая ошибка; смотрите Console.
- Вместо объекта undefined: забыли return или вернули результат только в части ветвей.
- STUDENT при subtotal=1000 даёт бесплатную доставку: сравнивается сумма до скидки.
- Число "2" принимается: появилось неявное или явное приведение типов.
- Второй одинаковый заказ отличается: изменяется вход или расходуется общий склад.

Перед защитой вручную рассчитайте заказ {notebook:3,marker:3} со STUDENT и доставкой, затем проверьте. Ответ: subtotal=1020, discount=102, delivery=150, total=1068. Объясните каждую строку task и почему здесь не нужны запросы к серверу, классы и библиотеки.
