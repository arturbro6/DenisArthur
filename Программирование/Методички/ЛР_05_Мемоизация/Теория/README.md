# От повторного вычисления к кэшу и декоратору

Сначала прочитайте [основы Python](../../Начать_здесь/README.md). Эта часть объясняет синтаксис до применения в лабораторной.

## Кэш — словарь уже полученных ответов

```python
cache = {}

def square(x):
    if x in cache:
        print("Из памяти")
        return cache[x]
    print("Вычисляем")
    result = x * x
    cache[x] = result
    return result

print(square(3))
print(square(3))
```

Первый вызов напечатает «Вычисляем» и 9; второй — «Из памяти» и 9. Вход 3 служит ключом, результат 9 — значением. `if x in cache` проверяет наличие ключа. Кэш объявлен вне функции, поэтому остаётся между вызовами. Если создавать cache={} в начале каждого square, второй вызов не помнил бы первый.

Для дерева ключа root недостаточно: поддерево зависит ещё от высоты. `(height, root)` — кортеж двух чисел, пригодный ключ словаря. В постоянном общем кэше важны и правила построения. Внутри одного вызова итеративного построителя правила фиксированы, поэтому их можно не включать в локальный ключ. Числа и кортежи чисел хешируемы: Python может использовать их как ключи. Список или словарь в таком ключе дадут TypeError.

## Функция, которая возвращает другую функцию

```python
def decorate(function):
    def wrapper(x):
        print("Перед вызовом")
        return function(x)
    return wrapper

def double(x):
    return x * 2

double = decorate(double)
print(double(4))
```

Результат: «Перед вызовом», затем 8. Внешняя decorate получает функцию double. Внутри создаётся wrapper, которая помнит function и вызывает её. `return wrapper` возвращает саму функцию, не вызывает её. Такое сохранение доступа к имени внешней функции называют замыканием. Декоратор — способ заменить функцию подобной обёрткой. Запись `@decorate` над `def double` заменяет строку `double = decorate(double)`.

## Незнакомые записи из memo.py

| Запись | Зачем она здесь |
|---|---|
| `*args` в объявлении | Собрать позиционные аргументы в кортеж |
| `**kwargs` в объявлении | Собрать именованные аргументы в словарь |
| `function(*args, **kwargs)` | Развернуть эти аргументы обратно при вызове |
| `kwargs.items()` | Получить пары имя/значение |
| `sorted(...)` | Упорядочить пары по именам |
| `tuple(...)` | Превратить список пар в неизменяемый кортеж |
| `(args, tuple(sorted(kwargs.items())))` | Сделать ключ по обеим группам аргументов |
| `hash(key)` | Явно проверить возможность использовать ключ |
| `wrapper.hits += 1` | Увеличить число попаданий на один; это сокращение присваивания |
| `wrapper.misses` | Счётчик новых вычислений |
| `cache.clear()` | Удалить все записи словаря |
| `wrapper.cache_clear = cache_clear` | Прикрепить функцию очистки к обёртке |
| `@wraps(function)` | Сохранить имя и документацию обёрнутой функции |
| `@lru_cache(maxsize=None)` | Встроенный декоратор кэша без ограничения числа записей |

Например, f(2, b=3) получает args=(2,) и kwargs={"b":3}. Запятая в `(2,)` обозначает кортеж из одного элемента. В этой учебной реализации одинаковые именованные аргументы в разном порядке дают один ключ, но f(2) и f(x=2) могут занимать разные записи.

## Одинаковые значения и один объект

`==` сравнивает содержимое, `is` проверяет, один ли это объект памяти. Кэш может возвращать тот же словарь. Изменение его поля тогда видно по другому пути дерева и в следующем вызове. Поэтому в опыте отдельно проверяют равенство и совместное использование узлов. Это свойство нужно объяснить в отчёте, а не скрыть.

В итеративном кэше stack хранит тройки `(оставшаяся высота, значение, дети готовы?)`. `False` — сначала обработать детей, `True` — собрать родителя из готовых результатов. `stack.pop()` берёт последний элемент: здесь стек, не очередь. Высота детей меньше, поэтому зависимость завершается.

Холодный замер начинается с пустого постоянного кэша. Прогретый выполняется после пробного вызова. Время очистки и прогрева не входит в измерение. `timeit` измеряет выполнение, `statistics.mean` усредняет повторы, CSV сохраняет таблицы, matplotlib строит изображения. Их используем после того, как поняли кэш на square.

# Теория: от словаря к декоратору

## 1. Что является одной задачей

Поддерево определяется текущим значением, оставшейся высотой и правилами потомков. Одного значения недостаточно: дерево с корнем 1 и высотой 2 отличается от дерева с корнем 1 и высотой 4.

При правилах x+1 и x−1 два пути — влево-вправо и вправо-влево — приводят к одинаковому значению на одинаковой глубине. Поддеревья можно не строить дважды. Если повторов мало, обслуживание кэша может стоить дороже вычисления.

## 2. Минимальный кэш

```python
cache = {}
key = (height, root)
if key in cache:
    return cache[key]
```

Кортеж неизменяем и подходит ключом словаря, если его элементы хешируемы. Списки и словари как части ключа не подходят. Учебный декоратор рассчитан на числа, строки, кортежи и объекты функций, а не на произвольные изменяемые аргументы.

## 3. Обёртка и замыкание

Декоратор принимает функцию и возвращает другую функцию. Внешний словарь остаётся доступен внутренней функции после завершения объявления: это замыкание.

`*args` собирает позиционные аргументы в кортеж, `**kwargs` — именованные в словарь. В вызове `function(*args, **kwargs)` звёздочки выполняют обратное действие — передают собранные аргументы дальше. Ключ `(args, tuple(sorted(kwargs.items())))` включает обе группы; сортировка делает порядок именованных аргументов несущественным. В этом простом варианте `f(2)` и `f(x=2)` могут занимать разные записи — это не нарушает корректность.

`@memoize` над def эквивалентно замене имени функции её обёрткой после объявления. Если тело рекурсивно обращается по этому имени, следующие уровни тоже попадут в кэш. Внешняя переменная `cached = memoize(plain)` этого не обеспечивает: внутри plain всё ещё вызывает plain.

`@wraps(function)` переносит имя и документацию исходной функции. Он не ускоряет алгоритм. Атрибуты wrapper.hits и wrapper.misses — счётчики, cache_clear очищает словарь и обнуляет их.

## 4. Равенство и тождественность

`a == b` сравнивает содержимое, `a is b` — один ли это объект. Кэш возвращает тот же словарь. Изменение общего поддерева видно в нескольких ветвях; постоянный кэш может вернуть изменённый результат следующему вызову. Защита: не менять кэшированные значения, использовать неизменяемые структуры либо копировать на границе (с дополнительной ценой памяти/времени).

## 5. Как честно измерить

Холодный кэш — перед каждым отдельным измерением пуст. Прогретый — результат уже есть. Эти цифры отвечают на разные вопросы. Итеративный кэш в задании создаётся внутри вызова, поэтому отдельный прогретый сценарий для него не объявляется. Времена одного компьютера не предсказывают точные времена другого.
