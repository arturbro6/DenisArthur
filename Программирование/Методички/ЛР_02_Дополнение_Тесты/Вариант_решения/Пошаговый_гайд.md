# Пошаговый гайд с нуля

## Как выполнять шаги в своей папке

Сначала прочитайте [основы Python](../../Начать_здесь/README.md). В VS Code откройте именно `Вариант_решения` этой работы через File → Open Folder. Если скачали репозиторий ZIP, сначала распакуйте архив; внутри окна GitHub файлы не запускаются. Оригинальные примеры уже лежат здесь: перед редактированием сохраните их копию в другой учебной папке.

Для промежуточных упражнений создайте рядом `practice.py`; для запуска используйте терминал VS Code:

```bash
python3 practice.py
```

Каждый новый блок с указанием «замените» полностью заменяет содержимое `practice.py`. Не склеивайте все упражнения в один файл. После изменения сохраните файл, запустите и сравните результат с указанным. В терминале не должно быть `>>>`.

## Шаг 1. Начать с одного полного теста

Создайте practice_test.py рядом с add.py. Введите целиком:

```python
import unittest
from add import add

class TestAdd(unittest.TestCase):
    def test_duplicates(self):
        result = add([3, 3], 6)
        self.assertIsNotNone(result)
        self.assertEqual(len(result), 2)
        i, j = result
        self.assertTrue(0 <= i < len([3, 3]))
        self.assertTrue(0 <= j < len([3, 3]))
        self.assertNotEqual(i, j)
        self.assertEqual([3, 3][i] + [3, 3][j], 6)

if __name__ == "__main__":
    unittest.main()
```

В терминале выполните `python3 practice_test.py`. Ожидается `Ran 1 test` и `OK`. Восемь пробелов внутри метода — не случайность: четыре для class, ещё четыре для def. Условие __main__ расположено без отступа; unittest.main() имеет четыре пробела.

## Шаг 2. Прочитать проверки по порядку

Сначала проверяем, что результат не None, затем что его длина два; после этого можно безопасно извлечь i и j. Проверки границ не дают обращаться за пределы списка. assertNotEqual запрещает один индекс дважды; последняя строка проверяет сумму значений. Такая проверка допускает обратный порядок и разные правильные пары. В готовом test_add.py повторяющиеся строки вынесены в check_pair: это собственный вспомогательный метод, который вызывают через self.check_pair(...).

## Шаг 3. Составить минимум восемь разных сценариев

До копирования готового набора запишите вход и ожидаемое поведение: обычная пара; пара в конце; одинаковые числа; отрицательные; ноль; пустой список; один элемент; отсутствие пары; несколько решений. Укажите, какую ошибку обнаруживает каждый сценарий. Для отсутствия пары используйте assertIsNone, а не сравнение с нулём.

## Шаг 4. Запустить итоговый файл

Откройте test_add.py и сопоставьте с учебным тестом. Выполните `python3 -m unittest -v test_add.py`: это запускает именно итоговые 11 проверок и не смешивает их с practice_test.py. Для общего обнаружения используйте `python3 -m unittest discover -v` после удаления временного теста из рабочей папки.

## Шаг 5. Написать объяснение

В README перечислите группы случаев и ошибки, которые они ловят. Набор из восьми положительных сумм не заменяет восемь разных сценариев. В этом дополнительном задании оцениваются тесты; сверяйтесь с условием и не добавляйте непредусмотренные требования к типам входа.

## Дополнительный разбор после первых запусков

# Как выполнить дополнение

## 1. Запишите контракт

Два разных индекса в границах списка, правильная сумма, любой порядок; `None`, если пары нет. Не начинайте с копирования готовых тестов.

## 2. Составьте восемь сценариев

Для каждого запишите вход, ожидание и ошибку, которую тест должен поймать. Возьмите таблицу из теории как ориентир, придумайте свои числа. В этой работе несколько подходящих пар разрешены: это важное уточнение к исходной ЛР 2.

## 3. Напишите простой тест

```python
result = add([2, 7, 11, 15], 9)
self.assertIn(result, ([0, 1], [1, 0]))
```

Кортеж после запятой содержит два разрешённых результата. Для нескольких подходящих пар перечислять все ответы неудобно: проверяйте свойства результата, как в `check_pair` приложенного файла.

## 4. Разберите вспомогательную проверку

Сначала убедитесь, что результат не `None`, затем что он содержит два индекса, затем что индексы различны и лежат в границах. Только после этого обращайтесь к `nums[i]` и `nums[j]`. Последовательность важна: иначе сообщение об ошибке будет запутанным.

`with self.subTest(...)` подписывает, для какого случая произошёл сбой. Это не условие и не цикл, а контекст отдельной проверки внутри теста.

## 5. Проверьте полезность тестов

Временно разрешите в реализации `j=i` — должен упасть случай с одним элементом. Верните исправный код. Временно поставьте `return None` после первой неподходящей пары — должен упасть пример с парой в конце. Это контролируемые изменения для проверки тестов; ошибочные версии в итоговый проект не включайте.

## 6. Оформите README

Создайте таблицу «имя теста → правило → какую ошибку находит». Не пишите «покрыты все возможные ошибки»: конечный набор тестов этого не доказывает. Команда запуска: `python3 -m unittest -v`.

## Самостоятельный шаг

Добавьте вход, на котором результат `[0,1]` неверен, а другая пара верна. Покажите, что проверка свойств принимает корректный результат и отвергает неверный. Приложенный вариант содержит 11 тестовых методов, но для сдачи вы должны уметь обосновать собственный набор.
