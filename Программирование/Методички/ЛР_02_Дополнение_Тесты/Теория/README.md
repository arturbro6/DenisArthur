# Тесты без предварительного знания классов

Сначала прочитайте [основы Python](../../Начать_здесь/README.md). Эта часть объясняет синтаксис до применения в лабораторной.

## Что означает тест

Тест автоматически вызывает нашу функцию и сравнивает поведение с заранее известным правильным. Код решения хранится в add.py; проверки — в test_add.py. Имена не заменяют друг друга.

```python
import unittest
from add import add

class TestAdd(unittest.TestCase):
    def test_duplicates(self):
        result = add([3, 3], 6)
        self.assertEqual(result, [0, 1])
```

`import unittest` подключает встроенный набор проверок. `class` объявляет группу тестов; имя TestAdd мы выбрали сами. `(unittest.TestCase)` даёт готовые методы assert. `def test_duplicates(self)` объявляет одну проверку. `self` обязателен здесь как параметр метода: он обозначает текущий тест и позволяет вызвать `self.assertEqual`. При обычном вызове add этот параметр не нужен. У тела класса четыре пробела; у тела метода восемь.

`assertEqual(a, b)` проверяет равенство; `assertNotEqual` — различие; `assertIsNone` — именно None; `assertIsNotNone` — не None; `assertTrue` — истинность; `assertIsInstance(i, int)` — что i целое. Это вызовы готовых методов, а не новый язык.

Точное ожидание [0, 1] выше подходит нашему перебору для обучения синтаксису, но общий контракт допускает обратный порядок. В итоговых тестах проверяем свойства: два разных допустимых индекса, сумма элементов равна target. Когда решений несколько, не требуем конкретную пару.

В приложенном файле `check_pair` — наш вспомогательный метод, имя не начинается с test_, поэтому отдельно не запускается. `(add, add_fast)` — кортеж двух функций; цикл проверяет обе. `with self.subTest(...)` помечает вариант проверки в отчёте, не меняя алгоритм. `function.__name__` получает имя проверяемой функции. `i, j = result` раскладывает пару индексов. `0 <= i < len(nums)` проверяет обе границы.

`nums.copy()` делает копию списка для сравнения до/после вызова. Конструкция `if __name__ == "__main__": unittest.main()` разрешает запускать файл напрямую. Однострочные test_методы можно переписать на две строки с отступом — смысл тот же.

# Как придумать тест, а не просто повторить пример

Тест состоит из входа, ожидаемого поведения и объяснения, какую ошибку он найдёт. Сначала изучают спецификацию, затем выбирают вход. Если ожидание вычислить тем же алгоритмом с той же ошибкой, тест может оказаться бесполезным.

| Ситуация | Что обнаруживает |
|---|---|
| Один элемент `[3]`, сумма 6 | Повторное использование одной позиции |
| Два одинаковых `[3,3]` | Ошибочное удаление дубликатов |
| Отрицательные числа | Неверное предположение «числа положительные» |
| Пара в конце | Преждевременный `return None` |
| Несколько пар | Слишком жёсткое ожидание единственной пары |
| Пустой список | Ошибки обращения по индексу |

`class TestAdd(unittest.TestCase)` объединяет проверки. Это наследование готовых методов проверок, не обязательно глубокое знание ООП. `self` — текущий объект теста. Методы с именами `test_...` обнаруживаются автоматически. `assertIsNone` проверяет именно отсутствие результата; `assertEqual` — равенство значений; `assertNotEqual` — различие индексов.

Пример необоснованного теста: ожидать исключение на строковом `target`, если контракт говорит только о целых числах и ничего не обещает для других типов. Это новая спецификация, а не обязательный тест.

[Документация unittest](https://docs.python.org/3/library/unittest.html).
